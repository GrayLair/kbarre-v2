# Documentation Authoring

Use when documentation is requested or a behavior change requires documentation. Identify
the audience and document type from the request and nearby docs before writing.

Describe verified behavior, prerequisites, examples, failure modes, and ownership only
when they help the audience complete a task. Keep tutorial, how-to, reference, and
explanation content distinct. Preserve local style and links; do not invent commands,
support guarantees, or configuration. Validate examples against the code or clearly mark
them as illustrative.

# Implementation Plan

Use when a task has multiple files, non-trivial design choices, or needs a reviewable
plan. Base the plan on inspected code and stated requirements; do not create a plan for a
small obvious edit.

Include the goal and non-goals, relevant evidence, affected components, ordered changes,
contracts or migrations, validation, rollback where risk warrants it, and unresolved
decisions. Make each step independently reviewable and name the files or symbols when
known. Separate confirmed facts from assumptions. Do not implement the plan unless asked.

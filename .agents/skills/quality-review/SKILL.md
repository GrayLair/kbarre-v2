# Quality Review

Use for an explicit quality audit or release-readiness assessment, not as a default step
for every code change. Establish the applicable requirements from specifications, tests,
documentation, and code; label inferred requirements as inferred.

Assess functional behavior, test effectiveness, regression risk, observability,
maintainability, and relevant security concerns. Lead with actionable findings and cite
the evidence for each. Separate blockers from improvements, avoid generating process
artifacts that the user did not request, and do not modify code during a review.
